# Time Tracker — Google OAuth + Sheets API

Chrome Extension (React 19, Vite 8, Tailwind 4, TanStack Query, Axios, Manifest V3).
**Теперь без Google Apps Script, общего SYNC_SECRET и бэкенда.** Пользователи подключают свои таблицы через Google OAuth.

## 1. Перед обновлением

- Сохраните копию таблицы Google Sheets.
- В DevTools текущего расширения сделайте резервную копию локальных данных:
  `copy(JSON.stringify(await chrome.storage.local.get(null)))`
- Не удаляйте текущее расширение Chrome, не меняйте его ID. Хранилище привязано к ID расширения.
- Ставьте патч в **тот же каталог проекта**, из которого уже загружается `dist`.

## 2. Получите постоянный ID расширения

В `chrome://extensions` включите Developer Mode и скопируйте **ID** существующего Time Tracker — строку длиной 32 символа.

Для публичной версии лучше зарезервировать расширение в Chrome Web Store Developer Dashboard, чтобы получить его постоянный ID. В Google Cloud OAuth Client Item ID должен быть **именно этим ID**. Важно: если ID расширения изменится, текущие локальные данные станут недоступны новому расширению.

Не вводите выдуманный `key` в `manifest.json`. Если используете собственный стабильный public key, добавьте его до выпуска и проверьте сохранность extension ID. Приватный ключ в исходники не добавляйте.

## 3. Google Cloud Console

1. Создайте или выберите Cloud Project на https://console.cloud.google.com/.
2. **APIs & Services → Library**: включите **Google Sheets API**.
3. **Google Auth Platform → Branding**: заполните сведения об OAuth-приложении.
4. **Audience**: `External`, добавьте свои Google-аккаунты в Test users, пока приложение в Testing.
5. **Data Access**: выберите scope `https://www.googleapis.com/auth/spreadsheets`.
6. **Clients → Create client → Chrome Extension**. В поле **Item ID** введите точный ID расширения (32 символа). Скопируйте выданный Client ID.
7. Замените `YOUR_OAUTH_CLIENT_ID.apps.googleusercontent.com` в `public/manifest.json` на реальный Client ID.
8. НЕ добавляйте OAuth Client Secret и не используйте `VITE_SYNC_SECRET`/`VITE_WEB_APP_URL`.

Scope `spreadsheets` **sensitive**, Google может потребовать верификацию OAuth-приложения перед публичным релизом, privacy policy, домен, подтверждение, описание использования scopes и демонстрационное видео. В Testing доступ разрешён только добавленным тестовым аккаунтам.

## 4. Сборка

```bash
npm ci
npm run lint
npm run build
npm run test:smoke
```

Перезагрузите текущее unpacked расширение через `chrome://extensions` → Reload.
Проверьте, что каталог `dist/` содержит `background.js`, `manifest.json`, `index.html` и `assets/`.

## 5. Что увидит новый пользователь

После установки **не требуются Google Cloud Console, OAuth Client ID или Apps Script**.
Весь OAuth Client ID разработчик один раз добавляет в `public/manifest.json`
перед сборкой и публикацией. Его нельзя запрашивать у пользователей.

При первом открытии popup показывает **только два шага**:

1. **Войти через Google** — интерактивный запрос доступа к Google Sheets.
2. **Подключить таблицу** — вставить ссылку `https://docs.google.com/spreadsheets/d/<ID>/edit`.

Кнопка подключения активируется только после входа. Если Chrome уже имеет
действующее разрешение, расширение проверит его без появления нового окна входа.
После подключения автоматически открываются проекты и таймеры, синхронизация
запускается сама. При следующем открытии popup экран настройки не показывается.

**Старые данные:** если в браузере уже есть локальные проекты/записи, появляется
необязательный флажок переноса данных в новую таблицу. На чистой установке
этого флажка нет. При отключении или переключении таблицы локальная история
сохраняется отдельно и восстанавливается при повторном подключении той же таблицы.
Нельзя менять или отключать таблицу, пока таймер запущен либо на паузе.

Чтобы сменить таблицу: откройте раздел «Google Таблицы» под проектами,
«Настройки подключения» → «Выбрать другую таблицу». Отдельный вход не
понадобится, если Google разрешение ещё действительно.

Нажмите «Синхронизировать» для ручной проверки; фоновая синхронизация
продолжает работать автоматически.

## Схема Google Таблицы

Каждая вкладка — дата `DD.MM.YYYY` с шестью столбцами:

`Проект | Начало | Конец | Длительность | Время для трекера | Описание задачи`

Десятичные часы: 30 мин = 0.5, 45 мин = 0.75, 90 мин = 1.5. Колонка Е пересчитывается из D. Стабильные ID проектов и сессий остаются только в Google Sheets developer metadata, без дополнительных видимых столбцов.

Поддерживаются синхронизация в обе стороны, редактирование строк напрямую в таблице, удаление сессии и проекта из расширения и обновление названия проекта. Записи до полуночи и после неё попадают в разные вкладки.

## Фоновая синхронизация

Service Worker `src/background.js` синхронизирует данные по Chrome alarm примерно каждую минуту. Если интерактивная авторизация истекла, пользователь открывает popup и нажимает вход снова. В фоне Google OAuth UI не показывается.

## Ограничения

- **Google OAuth Client ID нужно создать самостоятельно**, поэтому в готовом архиве в манифесте стоит placeholder. Пока он не заменён, вход не запустится.
- Доступ `spreadsheets` позволяет приложению работать со **всеми** таблицами аккаунта в пределах scope. Расширение использует только указанную пользователем таблицу, но Google разрешение глобальное.
- Chrome Storage содержит локальные проекты и историю; Google Sheets не является транзакционной БД. Одновременные изменения из нескольких устройств имеют риск конфликтов; для полноценного multi-device нужны версии записей и политика разрешения конфликтов.
- Разделять одну и ту же таблицу между разными Google-аккаунтами допускается только с правами на редактирование, но полная изоляция аккаунтов внутри одного Chrome-профиля пока не реализована: меняйте аккаунт через отдельный профиль Chrome.
- Сохранены старые Apps Script исходники в `legacy/` только как архив. **Их больше не нужно деплоить.**
- Фоновый alarm может срабатывать позже ожидаемого; обновления не являются мгновенными.

## Проверка без npm

```bash
node --test tests/*.test.mjs
```

Проверяются локальные операции, создание/удаление записей, переименование, синхронизация 6 столбцов и ручные изменения с имитацией Google Sheets API. Живую OAuth-авторизацию и выполнение запросов к реальному аккаунту нужно протестировать после указания вашего Client ID.

## Проверка чистого первого запуска

Используйте отдельный профиль Chrome с тем же Extension ID, что указан в
OAuth Client, и отдельную тестовую таблицу с правами на редактирование.
Проверьте первый запуск, вход, подключение, создание проекта/сессии,
запись в шесть столбцов, удаление и переименование, отключение и повторное
подключение той же таблицы. Не удаляйте рабочее расширение для тестирования.

`npm run test:smoke` включает сценарии подключения, отключения и восстановления
локальной истории. Для проверки реального Google OAuth требуется собственный
Client ID, доступный Google-аккаунт и запуск расширения в Chrome.
