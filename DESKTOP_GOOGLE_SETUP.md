# Time Tracker Desktop — Google OAuth + Sheets (этап 2)

Подготовлено на основе архива ветки `dev-desktop`, полученного 18 ноября 2026. Chrome Extension остаётся в прежней сборке `npm run build`; desktop использует `npm run desktop:build` / `npm run desktop:dev`.

## Что изменилось

- **OAuth для Electron**: вход через системный браузер, OAuth 2.0 Authorization Code + PKCE (S256), случайные `state` и loopback callback на `127.0.0.1`, динамический порт. Внутри popup WebView Google не открывается.
- **Вызовы Google Sheets API**: выполняются в Electron `main` через ограниченный IPC, а не с OAuth-токеном в React.
- **Токены**: хранятся локально в `google-oauth.enc` в `app.getPath('userData')`, зашифрованы `electron.safeStorage` (ключ хранит ОС). На системах без защищённого хранилища вход отклоняется.
- **Синхронизация**: используется существующая `directSheetsSync.js` без изменения логики чтения и записи; работает первоначальная загрузка, ручная синхронизация, и периодическая сверка приблизительно раз в минуту **пока окно открыто**.
- **Локальная работа**: доступна без подключения таблицы. Можно перенести локальные данные при первом подключении (чекбокс).

## 1. Google Cloud

1. Открой [Google Auth Platform / Clients](https://console.cloud.google.com/auth/clients) в **существующем** проекте Time Tracker.
2. Нажми **Create client → Desktop app**, название `Time Tracker Desktop`.
3. Скопируй **Client ID** (заканчивается на `.apps.googleusercontent.com`).
4. **Не используй** Client ID типа `Chrome Extension` и не меняй `public/manifest.json`.
5. Google Sheets API должен быть включён в этом проекте. Пользователь должен иметь права редактора на подключаемую таблицу.
6. В режиме Google OAuth Production клиент использует те же ограничения/проверку чувствительного scope `spreadsheets`, что и Chrome-версия.

## 2. Конфигурация

Открой `electron/oauth-config.js`:

```js
export const desktopClientId = '123456789012-XXXX.apps.googleusercontent.com';
```

Вставь свой настоящий **Desktop Client ID**. Никаких redirect URI вручную добавлять не нужно: Google для Desktop app разрешает loopback redirect с динамическим портом. `client_secret` сюда не вставлять; это публичное desktop-приложение.

## 3. Установка патча и проверка

Работай в ветке `dev-desktop`:

```sh
git switch dev-desktop
npm run lint
npm run test:smoke
npm run desktop:build
npm run desktop:dev
```

Если зависимости ещё не установлены: `npm install` (без `sudo`).

Сначала протестируй с отдельной Google Таблицей или её копией. Проверка на настоящей таблице у автора патча не выполнена.

## 4. Первый запуск

1. В Electron можно пользоваться локальными проектами как раньше.
2. Внизу открой раздел **Google Таблицы**, нажми **Войти через Google**.
3. В системном браузере выбери аккаунт и разреши доступ к Sheets.
4. После возврата в Time Tracker вставь ссылку на таблицу. Если хочешь добавить ранее созданные локальные проекты и сессии, **поставь галочку переноса**, иначе начнётся новый профиль для этой таблицы.
5. Нажми **Подключить и начать работу**. Проверяй синхронизацию, создание/переименование/удаление сессий сначала на тестовой таблице.
6. Чтобы пользоваться той же историей, что и в Chrome Extension, подключи **ту же ссылку**, но сначала проверь, что синхронизация Chrome завершена.

**Останови активные таймеры на обоих устройствах при первом подключении.** Одновременное ведение одной и той же сессии на двух устройствах не поддерживается и может дать конфликт. Два разных приложения одновременно могут читать и изменять таблицу; при конкурентных правках нужна дополнительная стратегия разрешения конфликтов.

## 5. Безопасность и ограничения

- Токены не возвращаются через `preload` в React; только `authenticated` и ответы Sheets API.
- `safeStorage` обеспечивает системное шифрование токенов, но безопасность устройства и учётной записи ОС остаётся ответственностью пользователя.
- Desktop `Client ID` не является приватным секретом. Не сохраняй refresh token или OAuth `client_secret` в репозитории.
- Фоновая синхронизация **при полностью закрытом окне** не реализована в этом этапе. Трей, автообновление и упаковка `.dmg` — дальнейшая работа.
- Приложение пока требует ручного `npm run desktop:dev` или `npm run desktop:start`; это **не готовый установщик**.
- Если Google возвращает `invalid_grant`, отключи таблицу и авторизуйся повторно. При другом Google-аккаунте убедись, что он имеет права на выбранную таблицу.

## 6. При проблеме

- `Укажите Client ID типа Desktop app` → исправь `electron/oauth-config.js`.
- `redirect_uri_mismatch` → убедись, что клиент типа **Desktop app**, а не Web application или Chrome Extension.
- `Нет соединения с Google Sheets API` → проверь интернет, Sheets API и сетевые ограничения.
- `403` → проверь права редактора и разрешение scope `spreadsheets` для аккаунта.
- Ошибка `safeStorage` → убедись, что доступно системное хранилище ключей; приложение не хранит токены открытым текстом.
- OAuth окно не закрывается автоматически: после сообщения в браузере вернись в Electron.
